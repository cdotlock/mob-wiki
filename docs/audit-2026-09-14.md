## Further improvements

1. **Sources and ownership:** 46 of 87 Markdown files (including index/log) have no source references. There are 26 source-reference occurrences that do not resolve locally, including other repositories and personal machine paths. Preserve the clues; replace with verified repository links or ingest actual sources when available. Assign owners for IDE, backend, assets and product pages.
2. **Historical deployment state:** the last pre-maintenance commit is July 2. Pages include pending deployments, superseded designs and older contracts. The migration synthesis has a newer committed source. A green structure check does not establish current production state; cross-repository revalidation remains separate work.
3. **Publication scope:** the repository is public and includes architecture and operations documentation. No complete credential scan, credential rotation, visibility change or history rewrite was performed. Confirm intended public scope with the owner.
4. **Editorial rules:** schema.md recommends long reference-grade pages while also suggesting splitting at roughly 500 words; SKILL.md repeats the short-page rule. Resolve this contradiction before a large rewrite. Three pages exceed 500 lines, but length alone is not a defect.
5. **Links and retrieval:** lint validates Wiki target pages, not every fragment or ordinary Markdown source link. Chinese fallback is literal substring search, not semantic retrieval. Improve these based on real failed team queries.
6. **Concurrent editing:** clients should supply expected_revision. Older clients omitting it retain last-write-wins behavior. Separate clones still require Git conflict resolution. The local viewer is not an authenticated public portal.
